# BirOvoz Local — Chrome-расширение

Локальная боковая панель: **English audio → Uzbek/Kazakh dub**, запись микрофона,
загрузка аудио, последовательное воспроизведение NDJSON-частей, Stop,
повторное прослушивание и скачивание полного WAV.

Это клиент существующего BirOvoz, а не отдельный TTS-движок.
Python, Sayro, Seed-VC, модели и API-ключи остаются в backend на вашем ASUS.
Расширение не делает обработку бесплатной и не добавляет казахское клонирование.

## Установка на Windows

1. Распакуйте `BirOvoz-Chrome-Local.zip` в постоянную папку, например
   `C:\Projects\BirOvoz-Chrome-Local`. Не запускайте расширение из ZIP.
2. Откройте Chrome и введите в адресную строку **chrome://extensions**.
3. Включите **Режим разработчика / Developer mode** справа сверху.
4. Нажмите **Загрузить распакованное / Load unpacked**.
5. Выберите папку, в которой непосредственно лежит `manifest.json`.
6. Через значок пазла закрепите **BirOvoz Local**, затем нажмите его значок.
   Откроется боковая панель. Требуется Chrome 116 или новее.

Если используете изменения в репозитории, загружайте папку
`product/chrome-extension`. Пересборка, npm и установка зависимостей не нужны.
После изменения файлов нажмите Reload на карточке расширения и заново откройте панель.

## Подключение BirOvoz

Существующий backend нужно запустить на **том же компьютере**, где работает Chrome.
Если сервер уже запущен, второй экземпляр не запускайте.

Из корня вашего настроенного BirOvoz в PowerShell:

```powershell
.\product\backend\.venv\Scripts\python.exe -B -m uvicorn product.backend.main:app --host 127.0.0.1 --port 8000
```

Сохраните существующие настройки модели/окружения: эта команда не настраивает
Sayro, Seed-VC и OpenAI заново. Если ваша рабочая команда содержит дополнительные
переменные среды, используйте её. Привязка `127.0.0.1` ограничивает сервер этим компьютером.

В панели должно появиться **LIVE** или **MOCK**. Адрес по умолчанию —
`http://127.0.0.1:8000`. В «Подключение и проверка» можно изменить порт либо
переключиться на `localhost`. Произвольные адреса, LAN и внешние серверы
этой локальной версией не поддерживаются.

## Сначала проверить бесплатно

Раскройте «Подключение и проверка» и нажмите **Демо плеера · без API**.
Вы увидите фиксированный текст и услышите тихие тестовые звуки.
Демо не вызывает HTTP/backend, STT, перевод или модель и работает без сервера.
Проверьте Stop, повторное воспроизведение, скачивание WAV и новую сессию.
Это **не проверка качества голоса**.

Для мокового backend используется явная подпись MOCK. Перед каждым аудиозапросом
панель повторно проверяет `/health`: переключение MOCK → LIVE не должно
незаметно превратить бесплатную проверку в платный запрос.

## Реальная запись и перевод

1. Выберите Uzbek или Kazakh и доступный голос. Список получен от вашего backend.
2. Нажмите «Записать фразу» и разрешите микрофон. Говорите на английском.
3. Нажмите «Завершить запись». Можно прослушать входную запись.
   Запись автоматически завершается перед лимитом 30 секунд, но **не отправляется автоматически**.
4. Для LIVE явно отметьте разрешение платного запроса.
5. Нажмите «Перевести и озвучить». Части аудио поступают и воспроизводятся по порядку.
6. После полного завершения можно скачать полный WAV или прослушать его повторно.

Вместо микрофона можно загрузить английское аудио до 30 секунд / 10 МБ
(либо меньших лимитов, сообщённых сервером). Длительность и читаемость проверяются
в Chrome до отправки; backend остаётся окончательным валидатором.

Если Chrome не показывает запрос микрофона из боковой панели, нажмите
**Разрешение микрофона**. Откроется отдельная вкладка расширения: нажмите кнопку,
разрешите доступ и вернитесь в панель. Там не производится запись или отправка.
При отказе проверьте разрешения Chrome и Windows → Конфиденциальность → Микрофон.

Chrome может заблокировать автозапуск звука. Тогда нажмите «Продолжить» или Play
в самом плеере. Во время streaming перемотка относится к текущей части;
после завершения доступен полный WAV.

## Честные ограничения

- STT/перевод в текущем LIVE-тракте могут использовать платный OpenAI API.
  Локальный Uzbek TTS может перейти на облачный fallback. Выбранный голос не
  гарантирует полностью локальный цикл. Фактический провайдер указан в результате.
- Kazakh local-clone не поддерживается текущим Sayro → Seed-VC трактом:
  при этом выборе Kazakh использует стандартный OpenAI, как в веб-версии.
- Выбор TTS-провайдера через существующий API **общий для backend**. Другие
  вкладки/веб-версия могут его изменить. Не запускайте конкурирующие клиенты
  во время одного запроса; итоговая подпись провайдера важнее выбранного режима.
- Холодный старт может занять десятки секунд. Максимальное ожидание одного запроса
  в расширении — 6 минут. После ошибки/таймаута автоматического повторного запроса нет.
- Stop отключает клиент, запись и воспроизведение. Он не гарантирует прекращение
  уже запущенных GPU-вычислений. Они могут задержать следующий запрос.
- Акустический barge-in, hands-free повторная запись и захват звука вкладки
  не реализованы в этой первой версии расширения. Запись включается только по кнопке.
  Существующая веб-версия с её функциями не менялась.
- Прямого text-to-speech API в проверенной версии нет: текстовый редактор с
  неработающей кнопкой не добавлялся. Google-вход, история, синхронизация,
  Chrome Web Store и публичный сервер — отдельные этапы.
- Закрытие панели прекращает локальную запись/выдачу; результаты хранятся в памяти
  панели и очищаются при закрытии/новой сессии. Скачайте нужные WAV заранее.

## Разрешения и данные

Manifest V3 запрашивает только `sidePanel`, `storage` и HTTP-доступ к
`127.0.0.1`/`localhost`. Нет content scripts, доступа к истории, чтения страниц,
захвата вкладок, удалённого JavaScript или внешних шрифтов.
Chrome может показать предупреждение о доступе к localhost — это доступ к вашему API,
а не к произвольным сайтам.

В `chrome.storage.local` записываются только адрес backend и выбранный язык.
API-ключи, записи, транскрипты и согласие на платные запросы не сохраняются.
Согласие сбрасывается при переподключении и новой сессии.
Backend может вести свои логи; его политика хранения от расширения не меняется.

При ужесточённых CORS-настройках backend при необходимости разрешите точный
`chrome-extension://<ID>` вместо открытия доступа всем сайтам. ID виден на
chrome://extensions. Host permissions позволяют расширению обращаться к localhost;
серверные origin-проверки или middleware могут вводить дополнительные ограничения.

## Контракт и проверка

Проверена совместимость с master **78c932cfeda680429d6538bd991ccc42c13a9776**:

- `GET /health` — mock/live и ограничения;
- `GET /api/voice/status`, `POST /api/voice/provider` — доступность и выбор голоса;
- `POST /api/turn/stream` — multipart `audio`, `conversation_id`, `language`,
  `mode=dub`, `source_language=en`;
- NDJSON `meta → part* → done`, либо `error`.

Backend-файлы не изменены. Полученный текст выводится как текст, не HTML.
Оборванный поток, неправильный порядок частей и повреждённый WAV не выдаются
за полный результат. Заголовок Content-Type для multipart формирует браузер.

Из корня репозитория:

```text
node tests/test_chrome_extension.mjs
python tests/chrome_extension_browser.py
```

Второй сценарий требует Python Playwright, установленный Chromium и свободные порты
8000/8123; можно задать `CHROMIUM_PATH`. Он запускает интерактивную панель с тестовым
адаптером Chrome API, фиктивный микрофон и детерминированный локальный HTTP-стенд **без моделей/API**.
Не запускайте его поверх рабочего backend. Это проверка клиента, не голосового
качества и не реального Windows/NVIDIA-тракта.

Установка unpacked-расширений в текущей проверочной среде запрещена политикой
администратора Chromium; она не изменялась. Manifest, разрешения и service-worker
конфигурация проверены отдельно, но настоящий Load unpacked и разрешение физического
микрофона в боковой панели нужно подтвердить на ASUS по инструкции выше.
